# 桌面界面实施规范

## 设计依据与优先级

以用户提供的 [《米家桌面端 UI 设计规范》](米家桌面端_UI设计规范.md) 为视觉规范、[全屋智能设计系统展示板](米家全屋智能设计系统展示板.png) 为构图参考。本文件记录代码实施与适配约定，不修改原规范的设计目标。旧版的紧凑侧栏和无 Hero 首页已由本次桌面方案替代。

关键词：轻盈、温和、现代、简洁、低对比、大圆角、弱阴影、卡片化。产品面向家庭智能设备控制，使用浅色 Sidebar、状态卡片、设备图、趋势图与快捷控制组织信息。

## 画布与适配

| 分辨率    | 布局策略                                                                  |
| --------- | ------------------------------------------------------------------------- |
| 1920×1080 | 主设计基准；232px 浅色 Sidebar，首页十个模块同屏可见                      |
| 1366×768  | 220px Sidebar，设备改为三列，底部消息独立成行；页面纵向滚动，保持文字可读 |
| 2560×1440 | 1.15 倍渐进显示比例，提高大屏可读性                                       |
| 3840×2160 | 1.5 倍显示比例与内容宽度上限；保持设计比例与信息密度                      |

渐进比例与用户在设置中选择的缩放相乘，集中在 `styles/responsive.css`。大屏控制内容宽度，保留适当留白。桌面 Sidebar 贯穿所有页面；760px 以下保留窄屏降级支持，导航转为底部横向滚动。

## 设计系统

- 主色 `#00C9A7`，Hover `#00B99A`，Active `#00A98C`，浅背景 `#E9FBF7`。
- 页面背景 `#F5F7F8`，白色卡片，浅灰输入区域，边界 `#EDEFF0`。橙、蓝、紫仅作为功能辅助色。
- 字体使用 PingFang SC、Microsoft YaHei、Inter、系统字体回退；界面不依赖远程字体加载。
- 圆角使用 8 / 10 / 14 / 18 / 24px，常规卡片 16–18px，Hero 20px，按钮 10–12px。
- 间距使用 4px 倍数；页面边距 24–32px，模块间距 16–24px，卡片内边距 16–24px。
- 页面标题 28–32px，模块标题 18px；高密度首页允许收紧字号层级。设备图片表达产品类别，导航与操作统一使用 Lucide 线性图标。
- 明暗主题使用同一组语义变量。Sidebar 始终保持浅色，深色偏好仅调整工作区与卡片。默认主题为浅色。

颜色与尺寸的单一来源为 `src/styles/tokens.css`；布局、首页、设备、管理页和断点分别在对应样式文件维护。常规按钮反馈 150ms，模态框约 200ms；支持系统减少动态效果设置。

## 首页

1. 顶栏：家庭切换、搜索、刷新、通知、偏好设置、账号；应用内路由共用同一外壳。
2. 家庭 Hero：问候、室内温湿度与空气质量，明亮家居照片只作局部背景。
3. 天气：位置、气温、天气和空气质量，与 Hero 并列。
4. 常用场景：四个快捷卡片、语音与设备添加入口；执行保留确认。
5. 房间 Tabs 与设备卡片：默认展示八台代表性设备；搜索、房间、排序和在线筛选有效。完整列表在设备管理页。
6. 右侧家庭安防与摄像头预览。
7. 底部能耗、环境、消息三个面板；1920、2K、4K 下保持全屋状态可一眼浏览。

## 设备交互

设备名称与图示打开快速详情；快速详情可进入完整控制面板。右上角是电源或详情入口，收藏在独立区域。房间与开关状态置于名称下方，底部显示指标。

| 状态  | 表达与行为                                         |
| ----- | -------------------------------------------------- |
| 开启  | 浅青绿电源背景、绿色图标与状态文字                 |
| 关闭  | 浅灰按钮、待机或已关闭文案                         |
| 离线  | 轻微降低透明度、明确离线提示、写入禁用             |
| 异常  | 仅状态文字与小圆点使用红色，显示具体问题，控制禁用 |
| Hover | 弱阴影与轻边界强化；显示收藏入口；键盘焦点同样可达 |

完整详情覆盖空调、灯、扫拖机器人、摄像机、门锁。控制以读取到的 MIoT 属性、范围、枚举和只读能力为依据；门锁只展示可读取状态，不推测远程开锁能力。

## 内容真实性与交互范围

浏览器的演示家庭以轻量提示明确标识。设备属性、收藏、设置、场景与语音复用现有 API；真实账号继续使用 Rust 原生命令，演示与真实请求隔离。

天气、安防汇总、能耗、环境趋势、摄像机静帧、消息、成员和自动化规则目前使用独立的本地家庭模型。真实家庭未接入相应数据时显示服务空态，不展示示例数值。摄像机画面标记「示例画面」，不伪称 LIVE；播放按钮只预览静帧，真实视频流尚未接入。

本地规则可创建、启停和删除，但不自动执行。成员添加不发出外部邀请。设备配网明确为本地流程体验，不采集 Wi-Fi 密码、不连接真实硬件。房间和新增设备仅在当前演示会话有效；其他本地家庭偏好按家庭隔离保存。

全部页面的路由、交互和数据边界见 [页面覆盖与能力清单](PAGE_COVERAGE.md)。

## 图片与验收

家居照片保存为 `public/images/living-room.jpg`，来源 [Unsplash 图片资源](https://images.unsplash.com/photo-1600210492486-724fe5c67fb0)。图片用于 Hero 与明确标识的摄像机示例静帧，离线打包无需访问远程图片。设备图示为本地 SVG 类别插图，不声称是特定型号的产品图。

运行 `node scripts/capture.mjs` 更新四个目标分辨率与全部页面截图，使用 `MIHOME_E2E_PORT` 选择本地服务端口。预览文件位于 `docs/images/`。

视觉验收覆盖所有页面、五类完整详情、四个目标分辨率、明暗主题、200% 用户缩放、空态、离线、异常、错误重试、键盘与模态焦点回归。功能测试规则见 [前端规范](FRONTEND.md)。
